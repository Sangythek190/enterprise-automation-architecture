Workflow Patterns

6 Reusable Workflow Patterns

Each pattern below solves a specific operational problem. If you are building enterprise workflow orchestration, start by identifying which of these patterns applies to your order lifecycle.

Pattern 1: Order Orchestration
6 workflows — Use when: your order pipeline has manual routing between sales, credit, and fulfillment teams
  • Submit Order to CPE
  • Credit Check Approve
  • Credit Check Fail
  • Subscriber ID Assignment
  • Program ID Assignment
  • Contract Push to Contract Billing
Pattern 2: Fulfillment Orchestration
8 workflows — Use when: you have multiple product types that each need different activation sequences
  • All-In-One WebExecutive
  • All-In-One WebPro
  • Banner Ads / MRECs
  • Web Basic
  • Facebook Campaigns
  • Google Adwords
  • Google Call Only
  • Google Display Network
Pattern 3: Revenue Operations
5 workflows — Use when: billing drift between your platform and your billing system causes revenue leakage
  • Payment Failed Auto-Cancel
  • Contract Billing Sync
  • Billing Audit Report
  • Month-End Reconciliation
  • Commission Report
Pattern 4: Churn Intervention
3 workflows — Use when: cancelled accounts disappear without anyone attempting recovery
  • Order Cancelled → Retention Notification
  • 2-Day SLA Sales Task
  • Re-engagement Campaign
Pattern 5: Customer Lifecycle Management
5 workflows — Use when: account setup, identity assignment, and deactivation are handled manually
  • Welcome Account
  • Assign Subscriber ID
  • Product Deactivation Webhook
  • Self-Healing Product Activation
  • Account Data Cleanup
Pattern 6: Observability and Reconciliation
3+ workflows — Use when: you have no automated way to detect data drift or generate audit trails
  • Orders Audit Report (Kele's Report)
  • TRUD Data Reconciliation
  • YepSync Data Migration

The Methodology

How to Build This: 6-Step Methodology

This is the product management methodology used to discover, design, and ship 30+ workflows. Each step is repeatable — apply this framework to any enterprise workflow orchestration project.

1

Step 1: Value-Stream Mapping

Conduct value-stream mapping across the full order-to-cash lifecycle. At Telkom, this revealed 30+ manual touchpoints across 5 teams (sales, credit, fulfillment, billing, retention). Document every handoff, delay, and failure point through stakeholder interviews and direct observation of operational workflows.

2

Step 2: Define Workflows Using Jobs-to-Be-Done

Use the Jobs-to-Be-Done framework to define each workflow's purpose: "When [trigger event], the system should [action] so that [outcome]." At Telkom, this produced 30+ event-driven workflows across 6 domains, each with defined trigger conditions, idempotent actions, and measurable outcomes tied to North Star metrics.

3

Step 3: Design Decision Trees with Circuit Breakers

Design decision trees with circuit-breaker patterns for every branch point. At Telkom, the credit decisioning branch either triggers downstream fulfillment orchestration (approve) or graceful degradation with sales notification (decline). Every branch must terminate in a measurable outcome — no dead ends.

4

Step 4: Build Revenue Reconciliation

Build a revenue reconciliation pipeline: platform state versus billing source-of-truth comparison. At Telkom, this catches billing drift before it becomes revenue leakage or a partner dispute. Includes Contract Billing sync, automated audit reports, and month-end reconciliation.

5

Step 5: Engineer Churn Intervention

Design churn intervention with SLA-driven escalation: payment failure triggers auto-cancel, which triggers a time-boxed win-back (2-day SLA at Telkom). Measure by save rate and mean time to intervention. If no contact in 24 hours, a re-engagement campaign fires automatically.

6

Step 6: Implement Self-Healing Patterns

Implement self-healing patterns with automatic retry and exponential backoff. At Telkom, if a product activation fails during fulfillment, the system retries automatically. If payment resolves after cancellation, the product reactivates without manual intervention. This reduces mean time to recovery (MTTR) and prevents support ticket escalation.
